A 45M tool-caller that cannot emit invalid JSON

Five days ago Cactus shipped Needle 2 — 45M parameters, 14MB, running on a microcontroller, scoring 63.7% on Google's Mobile Actions. We spent one working day and $27 building a model in the same size class. It scores 80.1%. This is why the gap exists, and it is neither scale nor a better mixer.

The bet

Tool calling is five decisions, not a generation problem

Most tool-calling models are language models that write JSON. Ours is a language model that makes five decisions, with the JSON assembled around it by a compiler.

Look at what a tool call actually requires. Given a query and a catalog of typed functions, something has to decide: does any tool apply, which one, which optional arguments the query licenses, what values go in them, and whether another call is needed. Every other token in the output — the braces, the quotes, the commas, and critically every argument key — is determined by the schema before the model runs.

A model that generates JSON as text spends capacity learning that { follows [. At 45M parameters you cannot afford that. So we don't.

The diagnosis

Where Needle actually loses

Needle 2's own table is the interesting part of their release: 98.3% name accuracy, 63.7% overall, 48.4% on two-call rows. They almost never pick the wrong tool. They lose on argument values, and on second calls that never get made.

The second number is a mechanism, not a mystery.

Their pipeline retrieves the top-5 tools once, then generates the call array as tokens. If the second call needs a tool outside that initial set, it was never a legal option — the model cannot recover, no matter how well it understood the query. The fix appears in a paper they don't cite: DTDR conditions retrieval on the query plus the calls already emitted. We re-run retrieval between array elements and swap the grammar's legal name set mid-generation.

Fig. 2 — The two-call gap, drawn. Needle scores 48.4 here; we score 66.0. The other half of the fix is a single token: after one call the model emits , or ], so that decision carries 6× loss weight in training.

The model

A trunk, three heads, and a compiler

A deep-thin transformer — d=448, 20 layers, GQA 8/4, SwiGLU, 8k BPE with tied embeddings, QK-norm, sandwich normalization, gated attention — carrying three capabilities:

1 · A retriever

Ranks the catalog against the query and the partial plan, re-running between array elements. This is the DTDR fix above.

2 · A name head

A bilinear readout scoring the decision-position hidden state against each candidate's name span in the prompt. The motivation comes from “Looking Is Not Picking”: models attend to the correct tool 80% of the time and still choose wrong. Tool selection fails at the readout, not at perception — readout-side interventions recover 59–91% of failures, prompt-side fixes at most 23%. So we replaced the readout with a trained one.

3 · A grammar-constrained argument decoder

The tokenizer holds a hard contract: JSON structural characters are singleton tokens that never merge into anything else. No token can straddle a structure/value boundary, so the compiler can force-feed structure exactly and consult the model only at the five choice points in Fig. 1.

Notably we did not clone Needle's Simple Attention Network. Their own paper prices that architecture against a matched-parameter transformer at 0.006 nats. The mixer was never the bottleneck — how the forward pass is spent is.

Fair warning

What is unfair about this comparison

Cactus states their asymmetries openly. So will we — in both directions.

Precision favors us

We report bf16. Needle reports CQ2-bit, measured end-to-end through a shipped C++ binary with a 256-token sliding window and cache eviction live. Quantizing to 2 bits will cost accuracy we have not yet paid.

Domain adaptation favors us

Mobile Actions' train split — 8,693 public rows, disjoint from eval — is in our mix. Needle trained on its own device-action corpus. Our eval rows were never seen, so the number is clean; but this is a domain-adapted model measured against a generalist.

Deployment favors Needle, enormously

They ship a dependency-free 14MB binary that runs on an ESP32 inside a 28MB RAM ceiling, with 2-bit QAT trained from pretraining onward. We have a 168MB bf16 checkpoint and no engine. On the axis they actually optimized for, we are not competitive.

Post-mortem

The first checkpoint scored zero

Not low. Zero. It refused half the rows outright and mis-selected the rest.

The cause wasn't capability. It was shape: we trained on catalogs of 3–9 tools, and Mobile Actions presents 10–16, with a date/time preamble on every query that our data never contained. The model had never seen the form of the question. Adding catalog augmentation and preambles moved it from 0.0 to 80.1.

Four bugs found by probing intermediate checkpoints, each of which would have silently corrupted the headline:

  1. Value truncation at 24 tokens. Email bodies cut mid-sentence, failing exact match on rows the model had otherwise answered perfectly.
  2. A device mismatch in the head/LM ensemble that crashed every constrained decode the moment it ran on GPU.
  3. Tokenizer alignment breaking on non-ASCII. <unk> is a five-character token string standing in for one character, which silently desynchronized every loss tag after it.
  4. A schema that lies. Mobile Actions advertises datetimes as YYYY-MM-DDTHH:MM:SS; its gold values use a space separator. We had written a grammar template from the schema text. Checking gold data instead of trusting prose caught it before it cost 365 rows.

Still open

What we don't know yet

The name head is on probation. Against the same-trunk ablation it wins by 1.5 points out-of-distribution with a small training set — and ties once the training set is large. The plan says we drop the heads if they can't beat the control. That verdict is pending on the harder suites.

Seal-Tools, DroidCall, BFCL v4 and ACEBench are still running or unbuilt. No claims are made about them here. Seal-Tools is the one that matters most: it holds out entire domains, which is the real test of whether the architecture generalizes or whether we simply learned Mobile Actions.

And 2-bit. Everything above is bf16. Needle's headline achievement is that their 14MB artifact is the model they trained. Ours isn't quantized at all yet, and that is the honest distance left between a benchmark result and a thing you can put on a doorbell.
